## 문서의 역할

- [기본 요구사항](../요구사항목록/요구사항.md), [XY 요구사항](../요구사항목록/요구사항_2.md): 기존에 문서화한 요구 범위.
- 이 폴더: 기존 요구사항 외에 추가한 기능의 목적, 실제 동작, 제약, 관련 파일과 검증 방법.
- [프로젝트 README](../README.md): 실행 및 사용 안내.
- `PROJECT_STRUCTURE.yaml`: 파일 구조 및 수정 위치 안내.

## 기록 방식

1. 추가 기능마다 `ADD-001`처럼 고유 ID와 `001_기능명.md` 파일을 부여한다.
2. 작성일, 확인 기준 커밋/브랜치, 원래 요청의 확인 가능 여부를 구분한다. 확인할 수 없는 요청일·원문·설계 의도는 추정하지 않는다.
3. 기능을 식별 가능한 항목으로 나누고, 각 항목을 구현 파일과 테스트에 연결한다.
4. 구현 사실, 현재 제약, 향후 요청을 구분한다. 테스트 정의가 존재하는 것과 실제 실행하여 통과한 것은 별도로 기록한다.
5. 동작이 바뀌거나 기본 브랜치에 반영되면 상세 문서의 변경 기록과 이 목록을 갱신한다. 관련 README와 구조 YAML이 있으면 함께 갱신한다.

이 목록은 현재 네트워크 추가 구현부터 기록한다. 기존 요구사항과 코드의 모든 차이를 전수 조사한 목록은 아니다.
