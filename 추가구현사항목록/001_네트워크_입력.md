## 1. 추가한 기능의 범위

외부 프로그램이나 파일에서 제공한 데이터를 Lua 스크립트가 네트워크로 받아 GPIO/PWM/DAC 제어에 사용할 수 있다. 함께 제공하는 예제는 프레임별 X/Y 점 좌표를 두 DAC에 출력하여 기존 XY 화면에 산점도로 표시한다.

[기본 요구사항](../요구사항목록/요구사항.md)은 핀, 스크립트, 파일 입출력, 계측기 및 시뮬레이션 동기화를 정의하고, [XY 요구사항](../요구사항목록/요구사항_2.md)은 두 채널 전압의 XY 표시를 정의한다. 두 문서에는 HTTP/WebSocket, 외부 데이터 서버, TCP/UDP 중계, Parquet 데이터 제공이 명시되어 있지 않다. 아래는 그 밖에 실제 추가된 구현이다.

## 2. 데이터 흐름

```text
데모 / Parquet → Python 데이터 서버의 HTTP API 또는 /ws
외부 UDP/TCP 프로그램 ↔ Python 데이터 서버의 /relay
                                  ↕
                   브라우저 NetHub (fetch / WebSocket)
                                  ↕
                         Lua API / 사용자 스크립트
                                  ↓
                 기존 보드 출력 → 필터/프로브/커플링 → XY 또는 Y-T
```

수신 데이터를 스코프에 직접 주입하는 별도 채널은 없다. 스크립트가 데이터를 해석하고 기존 출력 API로 보드에 반영한다. DAC 출력에는 기존 DAC 양자화, 필터, 프로브, 커플링, ADC 및 XY 획득 모델이 적용된다.

데이터 서버는 브라우저 앱과 별도 프로세스이며 앱 파일을 제공하지 않는다. 앱은 `index.html`로 열고 서버는 기본 `127.0.0.1:8000`에서 데이터를 제공한다. `index.html`은 `js/net.js`를 Lua 실행기보다 먼저 로드한다.

## 3. Lua API

### HTTP

| API | 현재 동작 |
|---|---|
| `http_request(url [, opts])` | 요청 핸들을 즉시 반환. `{url=..., ...}` 테이블 하나로도 호출 가능 |
| `req:ready()` | 결과 준비 여부 확인 |
| `req:result()` | 완료 시 `body, status, headers`, 통신 실패 시 `nil, 오류`, 미완료 시 `nil, "pending"`. 완료 결과는 핸들에서 재조회 가능 |
| `req:wait([timeout])` | 결과 또는 시뮬레이션 시간 초과까지 스크립트 대기. 시간 초과 시 `nil, "timeout"` |
| `req:cancel()` | 미회수 요청 취소. 이후 결과는 `nil, "cancelled"` |
| `http_get(url [, opts])` | 요청 후 대기. `opts.timeout`으로 대기 제한 지정 |
| `http_post(url, body [, opts])` | 본문을 포함한 요청 후 대기. 기본 method는 POST |

요청 옵션은 `method`, `body`, `headers`, `content_type`, `net_timeout`이다. `http_request`는 method 생략 시 body가 있으면 POST, 없으면 GET을 선택한다. 본문이 있는 요청의 Content-Type 기본값은 `text/plain;charset=UTF-8`이며 변경할 수 있다. GET/HEAD에는 본문을 붙이지 않는다.

HTTP 404 등은 통신 실패와 구분하여 본문과 상태를 그대로 반환한다. 헤더 이름은 소문자로 정리하며 Lua에 보이는 헤더는 브라우저가 허용한 범위이다. `req:wait()` 시간 초과는 요청을 자동 취소하지 않지만, `http_get()`/`http_post()`의 대기 시간 초과는 내부 요청을 취소한다.

### WebSocket

| API | 현재 동작 |
|---|---|
| `ws_open(url [, {timeout, protocols, wait}])` | 기본적으로 연결까지 대기. `wait=false`이면 연결 중 핸들을 즉시 반환 |
| `ws:send(data [, mode])` | mode는 `auto`/`text`/`binary`. 기본 auto는 유효한 UTF-8이면 text, 아니면 binary 선택. 연결 중 송신은 큐에 보관 후 전송 |
| `ws:poll()` / `ws:available()` | 대기 없이 메시지 1개 반환(없으면 nil) / 대기 메시지 수 |
| `ws:recv([timeout])` | 메시지까지 대기. 메시지 또는 `nil, "timeout"` / `nil, "closed"` 반환 |
| `ws:state()` / `ws:error()` | `connecting`/`open`/`closing`/`closed` 상태 / 오류 문자열 또는 nil |
| `ws:dropped()` | 수신 큐 초과로 버린 메시지 수 |
| `ws:close([code, reason])` | 연결 닫기 |

함수형 별칭 `ws_send`, `ws_recv`, `ws_poll`, `ws_available`, `ws_state`, `ws_close`도 제공한다. 수신 바이너리는 Lua string에 원래 바이트로 전달하며 `string.unpack` 등으로 해석할 수 있다. 송신 시 `text`를 강제하면 UTF-8 디코딩을 거치므로 임의 바이너리는 `binary`로 보낸다.

## 4. 시간, 출력 및 종료 규칙

- 응답 대기는 스크립트만 잠들게 한다. 시뮬레이션 실행 중에는 보드/계측기 시간이 계속 진행하고 출력 레지스터는 마지막 값을 유지한다. 독립적인 하드웨어 PWM은 계속 동작한다.
- 비동기 요청과 `ready()`/`poll()`을 사용하면 기다리는 동안에도 스크립트가 다른 출력을 만들 수 있다.
- 콜백은 브라우저 이벤트 루프가 처리한 뒤 후속 틱에서 관측된다. 대기 재개는 이미 확정된 시뮬레이션 구간 직후의 보드 클럭 엣지에 맞춘다.
- `timeout`은 시뮬레이션 초, HTTP `net_timeout`은 실제 초이며 기본 15초이다. 실제 지연과 시뮬레이션 속도에 따라 결과가 보이는 가상 시각이 달라진다.
- Simulation Pause에서는 가상 시간이 멈추지만 브라우저 네트워크 및 실제 시간 기반 HTTP 제한은 진행할 수 있다. 대기 재개 처리는 시뮬레이션이 다시 진행할 때 수행한다.
- 실제로 잠들어 기다려야 하는 호출은 메인 Lua 코루틴에서 사용한다. 사용자 코루틴에서는 `ready()`/`poll()`을 사용한다. 이미 결과가 준비되어 대기가 필요 없으면 제한 검사 전에 반환할 수 있다.
- 스크립트 정지·재시작·정상/오류 종료 시 LuaRuntime이 HTTP 요청을 취소하고 소켓을 닫으며 큐를 해제한다.
- 실제 시간 400 ms를 넘겨 대기하면 창 2에 HTTP 응답/WS 연결/WS 수신 대기와 경과 시간을 표시한다.

## 5. 데이터 서버와 프로토콜

저장소 루트에서 실행한다. 데모/중계는 Python 표준 라이브러리만 사용하며 Parquet에는 `pyarrow`, `numpy`가 추가로 필요하다.

```sh
python tools/signal_server.py --demo
python tools/signal_server.py --parquet points.parquet --fps 30
python tools/signal_server.py --parquet points.parquet --frame-col f --x-col px --y-col py --flip-y
python tools/signal_server.py --demo --udp-port 9001 --tcp-port 9002
```

앱을 정적 서버로 여는 경우 데이터 서버와 포트를 구분한다. 데이터 서버 포트 변경 시 Lua 예제 BASE/URL도 맞춘다.

| 경로/명령 | 구현 내용 |
|---|---|
| `GET /api/info` | `frames`, `fps`, `max_points`, `total_points`, `dac_max`, `source`를 `key=value` 줄로 반환 |
| `GET /api/frame/<k>` | `x1,y1,x2,y2,...` DAC 코드 텍스트. `?fmt=bin`은 little-endian uint16 좌표 쌍. 범위 밖 번호는 404 |
| `GET /api/frames?start=k&count=n` | 한 줄에 한 프레임. count는 0~1000으로 제한하며 유효 범위 프레임만 반환 |
| `POST /api/echo` | 요청 본문 그대로 반환 |
| `POST /api/relay` | 중계 활성화 시 본문을 TCP 클라이언트/마지막 UDP 송신자로 전달 |
| WebSocket `/ws` | 프레임 명령 및 실시간 스트림. 바이너리 메시지에는 바이너리 echo |
| `info`, `frame <k> [bin]` | 정보/프레임 조회. WebSocket frame 번호는 프레임 수로 순환 |
| `stream [start] [count] [fps] [bin]` | 실제 시간 기준 fps로 push. count=0은 순환 스트림, fps 생략 시 소스 fps |
| `stop`, `ping` | 스트림 중단 / `pong` 응답 |
| WebSocket `/relay` | UDP/TCP 메시지 중계. 중계 옵션이 없으면 오류 후 닫힘 |

응답에 `Access-Control-Allow-Origin: *`를 추가하고 OPTIONS를 처리한다. 기본 호스트는 loopback이며 인증/TLS를 구성하는 서버 옵션은 없다. 브라우저 통신은 CORS 및 페이지 보안 정책의 영향을 받는다.

### 소스 데이터와 중계 규칙

- 데모: 기본 250프레임, 25 fps, 최대 3000점의 회전하는 점 구름. 프레임 수/점 수/fps를 CLI로 조정 가능.
- Parquet: long(한 행=점, frame/x/y 열)과 list(한 행=프레임, x/y 리스트) 형식 지원. 열 이름 자동 탐색/지정, 프레임 정렬 및 NaN/inf 좌표 제거.
- 전체 좌표 범위를 DAC 코드로 매핑. 기본 최대 코드 4095, 비율 유지, 여백 5%. Y 반전 및 축별 개별 배율 선택 가능. 보드 DAC는 12 bit이므로 `--dac-max` 변경 시 출력 범위를 맞춰야 한다.
- UDP 데이터그램 하나를 메시지 하나로 전달. TCP는 줄 하나를 메시지 하나로 전달하며 끝 CR/LF 제거.
- 브라우저 송신 내용은 모든 연결된 TCP 클라이언트에 LF를 붙여 전송하고 마지막 UDP 송신자에게는 원래 내용으로 전송. 중계 서버는 메시지를 좌표로 변환하지 않는다.

## 6. 재생 예제와 UI 연동

| 예제 | 구현된 재생 정책 |
|---|---|
| `examples/11_net_http_frames.lua` | 서버 정보 수신 후 후속 프레임 선요청(AHEAD=8). 도착 시 교체하고 미도착 시 이전 프레임 유지. 최초 연결 실패는 1 시뮬레이션 초 후 재시도 |

두 예제의 권장 setup은 `js/examples.js`에 정의한다. DAC1→CH1(X), DAC2→CH2(Y), XY Dot, 500 kSa/s, 20000점 및 CPI=0을 적용한다. CPI=0은 파싱 및 두 DAC 쓰기 사이에 명령어 시간이 끼어 유령 점이 생기는 것을 줄이는 예제 설정이다. `App.applySetup`은 CPI 미지정 예제 로딩 시 기본값 1을 적용한다.

예제 메뉴는 독립 `.lua`를 직접 읽지 않고 `VS.EXAMPLES`의 내장 코드를 사용하므로 양쪽을 함께 관리한다. `/relay`는 `/ws`의 `info`/`stream` 명령을 해석하지 않는다. 중계 데이터를 예제 12 방식으로 표시하려면 초기 명령과 파싱을 송신 포맷에 맞춰 조정해야 한다.

## 7. 현재 범위와 제약

- 브라우저 계층은 fetch/WebSocket이다. 직접 TCP/UDP 소켓을 여는 Lua API는 없으며 Python 중계 서버를 경유한다.
- HTTP는 전체 응답을 읽은 후 결과를 공개한다. 점진적 HTTP 청크 스트리밍 API는 없다.
- HTTP 미회수 요청 상한은 4096개이며 결과 회수/취소가 필요하다.
- WebSocket 큐는 1,000,000메시지 또는 256 MiB 초과 시 오래된 메시지부터 버리고 경고/버림 수를 남긴다. 최소 한 메시지는 보존하므로 단일 초대형 메시지에 대한 엄격한 256 MiB 상한은 아니다.
- 일반 API에는 자동 재연결/재시도 정책이 없다. 예제의 재시도, 프레임 유지 및 최신 프레임 선택은 스크립트 정책이다.
- 실제 도착과 가상 시간은 독립적이므로 고정된 가상 도착 시각이나 모든 프레임 보존을 보장하지 않는다.
- JSON/CSV/바이너리 등 데이터 해석과 출력값 변환은 Lua 스크립트가 담당한다.
- 편집기 구문 강조(`js/ui_editor.js`의 `API`)는 전역 함수 이름만 대상으로 한다. `req:ready()`, `ws:send()` 같은 메서드 이름은 강조하지 않는다.

## 8. 검증 방법

최근 실행 결과는 문서 상단의 검증 상태에 기록한다.

| 검증 | 실행 방법 | 정의된 확인 범위 |
|---|---|---|
| 모의 네트워크 | 브라우저에서 `tests/test.html#12` 또는 Git Bash의 `sh tests/run_tests.sh 12` | API, 대기 중 시계/출력, 시간 초과, 바이너리, 오류, 코루틴 제한, 정지 시 정리 및 예제 11·12 |
| 데이터 서버 | `python tests/test_signal_server.py -v` | HTTP/CORS/echo, WebSocket 명령/스트림, UDP/TCP 양방향 중계, Parquet 형식/변환. pyarrow/numpy 미설치 시 Parquet는 skip |
| 실제 연동 | `python tests/run_net_e2e.py` | 데모 서버 + headless Chrome의 file:// 페이지. HTTP/바이너리/POST/연결 오류, WebSocket 스트림 및 예제 11·12 |
| 실제 UI | `index.html`에서 예제 11/12 로딩 후 별도 서버와 사용 | XY Dot, CPI 전환, 대기 문구 및 Pause/STOP 조작. 자동 네트워크 테스트는 UI 스크립트를 로드하지 않음 |

코어/연동은 `RESULT ... fail=0` 및 EXCEPTION/NO OUTPUT 여부, 서버 테스트는 `OK`와 skip 여부를 확인한다. 실제 연동은 Python과 Chrome이 필요하며 `CHROME` 환경변수로 실행 파일 경로를 지정할 수 있다.
